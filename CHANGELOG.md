# Changelog

## Resource Planner & Heatmap (separate extension, `planner/`)
- **No Pie for fields with many values**: the Pie button is only offered when the chosen field has up to 12 values; for a field with more it is hidden, and a Pie chosen earlier (in the settings or a saved view) opens as Auto instead.
- **Executive Dashboard polish**: the numbers in the Go-live columns no longer get clipped (columns are wider, and an inner number or ✓ is shown only where it fits); the status donut is larger; the By-field table shows whole rows (eight, with a soft fade when there are more) and its rows are keyboard-focusable; in the Delivery pipeline the Epics that are ignored, not mapped or without a stage are now links that filter to them (“Stage: Not mapped”); on narrow screens the pipeline wraps, the By-field card uses the room it has, and the page no longer scrolls sideways.
- **By-field chart with five chart types** (Executive Dashboard report, top right): the “By …” card now has a **Auto / Bars / Columns / Pie / Table** switch. **Auto** picks from the number of values in the chosen field: columns up to 6 values or for an ordered field (P1, P2…, High / Medium / Low, in natural order), bars up to 12, and a **sortable table** above that (value, Epics, status mix, a count per status, % at risk, average progress, with a search box and a sticky header). **Pie** shows each value's share of the Epics with a ranked list beside it (status mix and % at risk), in neutral burgundy and grey so the status colours keep their meaning, with the smaller values merged into “Other”. A click on a column, bar, slice or table row filters the dashboard as before. The card has a fixed height (the table and long lists scroll inside it), so the other charts never move. Each category field can have its own default chart in Settings › Executive Dashboard › Epics, grouping and dates; the choice a person makes on the dashboard is kept in their saved views and shared links.
- **Delivery stages are now the core of progress and status** (Executive Dashboard): Settings › Executive Dashboard › Delivery stages and progress. Choose where the stage is read from (a field such as Delivery Status, the state, or the field with the state as fallback), define the stages in order (for example Design, Development, SIT, UAT, Deployment) with what each counts as in percent and its planned window as a share of the Epic's time, and map each value found to a stage (or “(ignore)”). Once stages are set up the stage **always** decides an Epic's progress; the percent field, the number fields and the grid are only used until then (they are kept in a collapsed block). Optional smoothing moves progress inside a stage with its planned window. New status rules: **behind for the stage** (Needs attention / At risk when the Epic is that many stages behind the stage it should be in for the time used) and **stuck in a stage** (more than N days, read from the work item history); the old progress-behind-time rule is not used while stages are on.
- **Delivery pipeline chart** in the report (bottom right, next to the charts): one column per stage with the status mix, average time in stage, Epics stuck and Epics behind, a banner naming where work is piling up, and a click on a stage filters the dashboard (a “Stage: …” chip, kept in saved views). The charts now sit in two columns, “By type” shows the top 8 with an “Other” row and a **Show all** button. The two columns always end on the same line: By type is a fixed-height area (few values get taller rows, many values scroll), the pipeline keeps its natural height and the two left charts share the same height equally, so there is no uneven or empty space.
- Every field picker in the Planner settings (RAG status, go-live date, category, progress and more) now also has a box to **type the field's reference name**, for example Custom.RAGStatus, for a field that is not in the list.
- **Simpler status rules**: by default the data status is now two rules: **At risk** when the go-live date has passed and the Epic is not done; **Needs attention** when progress is behind the time used by more than one number you set (15 points). The forecast days-late rule, limits per Epic field and per category move to a collapsed **Advanced rules** box (off by default; existing settings are kept). When the owner's RAG is the status shown, an Epic whose RAG looks better than the data gets a plain-language **Check this** note (for example “RAG is Green, but past its go-live date by 12 days and not done”) with a **RAG check** filter and card. Settings order: Declared status (RAG) comes before Status from the data. Note: Epics may count differently after this update because the forecast rule is no longer on by default.
- **Executive Dashboard**: the Comfortable / Compact switch is removed; the dashboard is always compact. A faint strip at the right edge (visible in browser full screen) was the shadow of the closed detail panel; the closed panel is now hidden.
- **Field labels**: category fields, the “By …” chart choice, filters, chips, the Epic panel, the Epic Gantt “Group by” list, the extra filter fields of the Planner (filter bar, chips and the filters drawer), the “Flagged: …” and limit-rule reasons, the go-live history notice and the saved-filter field list now show each field's own display name from the process (for example “Business Value”), not a name worked out from its reference name.
- **Delivery performance** card in the Executive Dashboard report (between the charts and the Epic table): the **on-time delivery rate** (with the change against the quarters before), **average days late**, **delivered against due** in the last finished quarter, **delivered within ± days**, a column per quarter (on time, late, late by more than a limit, the on-time rate above each) and the **biggest delays**. Everything is a setting (Settings › Executive Dashboard › Delivery performance): whether it is shown, where the delivered date comes from (the date the Epic's state last reached a done state, read from the work item history in the same pass as the go-live history, or a date field such as Closed date), the grace days that still count as on time, the second late band, the predictable range, the quarters in the chart and in the tiles, and which parts are shown. A Period filter sets the quarters shown; other filters apply. Each person can fold the card away; the choice is kept in saved views. Epics that are not done, reopened after Done, or have no go-live date are left out.
- **Period filter** on the Executive Dashboard: a “Period” pill in the filter row (and at the top of the Portfolio map's rail) with This quarter, Next quarter, This year, Last 12 months, Next 6 months and a Custom range; “All time” stays the default. What the period is compared with can be switched in the pill: **Active in the period** (start to go-live overlaps it; the default), **Go-live in the period**, **Created in the period**, or **your own date field**. Epics without a date to judge by are left out with a note, unless “Include Epics without a date” is ticked. The choice shows as a chip, narrows every layout, and is kept in saved views and share links (relative presets are counted from today again). Settings › Executive Dashboard › Dashboard: the default comparison, an own date field, and a period the dashboard opens with. Trend lines stay for the whole portfolio (“trend: whole portfolio” while a period is set). The Epic created date is now read; the first load after this update reads the Epics again.
- **Trends from the first day**: the sparklines and “vs last week” on the Executive Dashboard cards no longer have to wait for weeks of use. The first time, the earlier 8 weeks are rebuilt from the work item history (state, dates, progress fields, the declared status and the blocker flag as they were at each week's end, judged with your current rules) in the same pass as the go-live history, and stored (Settings › General › Go-live history › “Rebuild earlier weeks of the trend lines”, on by default). A week that was recorded is never replaced, and the “vs last week” tooltip says when earlier weeks were rebuilt. Not rebuilt: progress from grid ticks, go-live moves and over-capacity, since those cannot be read back. Until there are two weeks (or with a filter applied) the cards say “trend starts next week” or “trend: whole portfolio” instead of staying bare. The first load after this update reads the history again.
- **Done is deep green with a ✓**; On track is a brighter green with a dot (cards, legend, donut, bars, columns, map, roadmap, table). A ✓ also marks Done segments and tooltips, so the two greens are not told apart by colour alone.
- **Cleaner charts**: the status legend beside the donut is now regular page text (name and count, clickable); the “By type” bars are all the same width so small groups no longer collapse into dots (segments show the share of each status, the number after the bar its size, “% at risk” at the right); small columns keep a sensible shape and “No go-live date” reads “No date”.
- **Fewer, clearer notices**: the dashboard's data warnings (unrecognised RAG values, no go-live date, no progress value, no go-live changes recorded) are now one short **Data notes** line that opens for details, and their counts follow the filters (for the Epics shown, not all Epics). New setting **No RAG yet** (Declared status): values such as Not Started or N/A are treated like an empty field, without a warning.
- **Executive Dashboard access**: Settings › Executive Dashboard › Dashboard now has its own **access teams** (members of those teams and project administrators can open the dashboard; empty = the same people as the Resource Planner’s Access teams). The Epic table’s second column in the Owner’s RAG view is now simply **Data says**: the data status with a ✓ where it agrees, a ⚠ where the RAG looks better, or “no RAG”.
- **Seamless charts**: the “By type” bars and the “Go-live by quarter” columns have no gaps between segments (one rounded shape with thin white dividers and the count inside each segment); each type also shows its **% at risk** at the right. Clicking a segment or a label still filters.
- **Status view switch** (Owner’s RAG · Data · Variance) on the Executive Dashboard when a declared status field is chosen and the setting is not “Owner’s RAG decides”; the setting is the view the dashboard opens in, the choice is kept in saved views and share links, and the weekly trend lines show only for the opening view. **Owner’s RAG** and **Data** recolour every layout; the Epic table has just two columns that compare them (Status, captioned with where it comes from, then **Data check** in the RAG view — “✓ agrees”, “⚠ Data says At risk”, “No RAG” — or **Owner’s RAG** in the Data view, with a ⚠ where the RAG looks better than the data). **Variance** shows four counts (Check this, Owner more cautious, Matches, No RAG), a clickable 3×3 grid of owner RAG against data status, the biggest gaps to ask about and the table sorted by gap; the Portfolio map shows the data status with a coloured edge in the owner’s RAG.
- **Status source** (Data decides · Owner’s RAG decides · Owner’s RAG decides, data checks it, with a “Which to choose” note in the settings): when a declared status field (RAG) is chosen, the status shown can come from the data, from the RAG only, or from the RAG with the data as a check (the data status stays in the Epic panel and Epics where the owner is more optimistic than the data are flagged). Say which values mean green, amber and red, or leave them empty to recognise words like green, on track, amber, red, at risk, delayed. Done and Not started Epics keep their state.
- **Executive Dashboard settings are in seven numbered sections**, each with a one-line purpose: Dashboard, Epics grouping and dates, Progress, Status from the data (limits, per-Epic and per-category limits, signals), Declared status (RAG), Portfolio map and resources, Calculated fields and saved filters.
- **Settings has a sub menu**: General (Epics, go-live history, access and filters), Resource Planner (hours sources, capacity, period and colours, Epic Gantt grouping and statistics) and Executive Dashboard.
- **Subtle motion in the Executive Dashboard**: cards rise in one after another, the numbers count up, the health gauge, donut, bars, columns, sparklines and progress bars draw themselves, the map blocks and roadmap bars appear in a quick wave, a filter change eases the view in and the numbers move from the old to the new value, buttons and cards lift slightly on hover, and the Epic panel slides in. Everything is under a second and switched off when the person's system asks for reduced motion. The Epic Gantt and Settings get only small hover and slide effects.
- **Executive Dashboard is a portfolio view**: team, hours booked and the over-capacity check are off by default (Settings › Executive dashboard › “Show resource information” brings them back). The map block size comes from a number field you choose (budget, value) or is one per Epic. **Limits follow the Epic**: each Epic can carry its own limits in number fields; otherwise the first matching rule (for example Type = Regulatory: attention above 0 days late, at risk above 14) applies; otherwise the global limits. The Epic panel says which was used. New optional signals: a **declared status** field shown next to the computed status with a “Declared vs data” filter and an “Owner more optimistic” card, **not updated for N days** and a **blocker / risk flag** field.
- **Executive Dashboard for large portfolios**: Roadmap bars no longer carry the title (it is in the name column; hover or click for details), so the go-live markers stay readable; a caption explains that a collapsed row\u2019s stripe is the status mix, not dates; the Portfolio map has larger group and block labels. Scorecards stay.
- **CBQ burgundy colours**: the purple/indigo accent and gradient are replaced by a burgundy palette (hero card, layout switch, buttons, selected filters, logo, Gantt statistics and go-live markers). Status colours (green, amber, red, grey, blue) are unchanged. The exact brand hex values can be swapped in one place if the bank's brand guide differs.
- **Polished look, always light**: the Executive Dashboard (all three layouts), the Epic Gantt and the Epic dialog have a refined design (portfolio health gauge, status cards with trend lines and "vs last week" changes, rounded charts, sliding layout switch, id chips, skeleton loading). The extension no longer follows the Azure DevOps dark theme; it is light everywhere.
- **Weekly snapshots**: the first person to open the dashboard each week stores the portfolio numbers (shared, refreshed at most every 12 hours, last 26 weeks) so trends and "vs last week" are real; the trend lines appear from the second week. Trends show only when no filter is narrowing the view.
- **Comfortable / compact** density toggle (Executive Dashboard and Epic Gantt) and a **Months / Quarters** header zoom on the Epic Gantt; both are kept in saved views.
- Resource Planner **Settings are for project administrators only**, and **Access teams** now works: when teams are chosen, only their members and project administrators can open the Planner, the Executive Dashboard and the dashboard widgets (a display guard; Azure DevOps still trims the Epics each person can read).
- Planner: the page uses the full width (no empty strip when the DevOps sidebar is collapsed); the plan starts **collapsed** (Settings › Plan rows start: collapsed / teams open / all open). **Epic Gantt** now shows Epic statistics instead of capacity tiles (portfolio progress, on track, late, due in 30 days, on hold and more; the administrator chooses the default set in Settings, each person can adjust it), clicking a state in the key or a statistic shows only those Epics (several can be selected), and the search box finds Epics by id or keyword.
- **Epic Gantt**: bars are coloured by the state's group in the process (Proposed, In Progress, Completed, Removed; read from the process, with a word match as fallback), so "Delivery Committed" is In Progress and "Cancelled" is grey; an Epic past its target date and not completed or removed (including On Hold) is a **red** bar. New Settings option: a field (e.g. Delivery Status) written at the end of each bar. Fixed: the Filters drawer was clipped by the toolbar; **Data & diagnostics** is now for project administrators only, like Settings.
- **Go-live history** (Settings › Go-live history, on by default; untick it to skip the first read through the revisions): reads every change of the Epic target date and the go-live date field from the work item history (the revisions report; the first read goes through all revisions, afterwards only new ones, cached in the browser). The Epic Gantt marks where the target date originally was (◇ and a red or green line to the current date, with the moves in the tooltip). The Executive Dashboard adds the same marker on the Roadmap, a “Go-live changes” column, a “Go-live moved” card, a “Go-live changes” slicer (moved later / earlier / 2+ times / recently / not moved), and a history timeline in the Epic panel and in the Epic dialog of the Epic Gantt, Timeline and Planner (read from the Epic's updates when the history of all Epics is off); on the Gantt a “2× +80d” label sits next to the ◇. An Epic whose date moved N times in the last X days can be raised to “needs attention” with the reason (switchable).
- **Executive Dashboard redesigned with three layouts** you switch between: **Report** (slicers, status cards, status donut, by-type bars, go-live-by-quarter columns and a sortable table), **Portfolio map** (a rail of filters with live counts, a map where block size is hours booked and colour is status, and the Epics that need attention) and **Roadmap** (a headline in words, a status bar, a roadmap with forecast slip, scorecards and a table). All three share the filters and one search box that finds anything (id, title, state, area, categories, reasons, people, dates, team). Clicking a chart, card, block or scorecard filters everything else; every Epic opens a detail panel. The Ask box and question chips are gone; the named filters of the settings are now a **Saved filter** list, calculated fields are extra table columns, and the layout the dashboard opens in is a setting. It also has personal saved views, full screen and a share link like the Planner. The dashboard's stylesheet was never loaded before; it is now.
- **Icons everywhere**: the toolbar buttons (expand all, collapse all, full screen, exit full screen, download CSV, refresh, filters, statistics, views, link, add, delete, save, discard, close and more) now use the same drawn SVG icons instead of symbol characters that depended on the installed fonts, in the Resource Planner, the Executive Dashboard and the grids (CSV, Excel, Import, add row, move, delete, expand all / collapse all).
- Planner **date format and month format** are set by the administrator (Settings › Display): dates such as 05/10/2026 or 5 Oct 2026, months such as 10/2026 or Oct 2026. They apply to the heatmap tooltips and details, Gantt and Timeline bars and tooltips, the Epic dialog and the Executive Dashboard dates; the custom period uses a month picker. The standard look stays YYYY-MM-DD / YYYY-MM until a format is chosen, and CSV exports keep YYYY-MM-DD / YYYY-MM so they open the same everywhere.
- **Epic Gantt grouping by an Epic field**: Settings › Epic Gantt grouping lists the fields (for example Delivery Status, Business Unit) that appear in the Gantt “Group by” list next to Area, State and Team. Groups sort naturally (3. Design before 10. Live) and Epics with an empty value go to a “(none)” group at the end. The choice is kept in saved views and shared links.
- Planner **Views**: each person can save the Heatmap / Timeline / Epic Gantt as they like it (view, grouping, units, period, team, query, filters, key selections, collapse level, Gantt statistics), name it, update, rename, delete and mark one as the one that opens by default. Views are stored per user (not shared). **Full screen** button for the Heatmap and Epic Gantt (hides the Azure DevOps menus and the page header; Esc exits). **Copy link** in the Views menu gives an address that opens the Planner with that view, full screen; people still need access to the Planner.
- The **Executive Dashboard is now its own board** (Boards › Executive Dashboard, always listed; it shows "not enabled" until the box in Settings is ticked). The Resource Planner has three tabs: **Planner** (heatmap, timeline and Epic Gantt are views inside it), **Data & diagnostics** (the former Data check and Diagnostics together) and **Settings** (administrators). The separate Heatmap, Resource timeline and Epic Gantt tabs are removed.
- Resource plan: **Group by** Team › Person › Epic, **Epic › Team › Person** (all Epics first, then teams, then people) or Person › Epic; toolbar tidied into two rows (view, grouping, units, expand/collapse · period, team, Epics, search, filters). Settings › Display: default view, grouping and units for the Planner.
- Planner heatmap is now a **resource plan**: each person has a ▸ expander showing their Epics (with hours per month), a frozen name and **Total** column, team header totals, a **Hours / % of capacity / FTE** switch and Expand all / Collapse all. All booked hours count as committed (no committed/requested split).
- New one-screen **Planner** tab (default): compact filter bar with removable chips and a filters drawer, KPI strip with clickable bands, Heatmap / Timeline / Epic Gantt switch, collapsible teams, linked month highlight, detail panel (Esc closes). The separate Heatmap, Resource timeline and Epic Gantt tabs remain.
- New **Executive** tab in the Resource Planner (off until “Enable the Executive Dashboard” is ticked in Settings; no separate menu item): every Epic with status (on track / needs attention / at risk / not started / not assessed / done), reasons, forecast finish, delivery confidence, a brief, category breakdown and an “Ask the dashboard” box that turns a question into filters (no AI; numbers come from the data). Category fields, go-live date, progress sources (percent field, completed ÷ total, ticked grid rows), states and limits are set in Settings › Executive dashboard.
- Heatmap, resource timeline, Epic Gantt, three dashboard widgets (utilization, over capacity, team map), Diagnostics tab, keyboard-accessible tabs, Marketplace page. Read-only (`vso.work`, `vso.project`). Pilot checklist: `docs/planner-pilot-checklist.md`.

## 2.2.0 (next)
**Resource Capacity**
- Automatic grids such as Resource Capacity show read-only cells as plain text (nothing cut off, numbers right-aligned under their headings, people shown by name with the full address on hover).
- Rows with hours on other Epics get a ▸ expander: it opens the list of those Epics right under the row (id chip, title, hours lined up under "Hours (other Epics)", each Epic's share of the person's available hours, and a total), with Expand all / Collapse all; the filter also finds Epics by title and a click opens the Epic. Read-only; exports stay flat rows.

**Reliability**
- Capacity records and live allocations now use short, fixed-length ids. Long ids were seen to be mistaken for each other on Azure DevOps (each new audit entry replaced the previous one). Older records are still read, de-duplicated, and can be moved with **Diagnostics → Move to short ids**.
- Saving the settings is version-checked: if another administrator saved in the meantime you can load their version or overwrite. Preset saves from work items retry on a clash.
- New **Diagnostics** tab: storage, id length limit, version check, permissions, teams/members/fields/capacity reads, settings consistency; results can be copied.

**Features**
- Grid columns can be **hidden** (Grids tab › column › “Hide this column in the grid”): they are still calculated and saved and can feed other columns, totals and status columns, but are not drawn, so a rating can be shown without the weights and scores behind it.
- The Boards **Capacity** page is gone: the capacity register editor and the utilization overview are shown in the hub's **Capacity** tab, and only when the capacity register is the capacity source (nothing to maintain when capacity comes from Azure DevOps team capacity).
- **Fix (Server 2020):** the audit log failed with “localeCompare is not a function” because stored date-like text came back as Date objects; documents are now turned back into text.
- Grid formulas can total a column per group: `GROUPTOTAL`, `GROUPAVG`, `GROUPMAX`, `GROUPMIN`, `GROUPCOUNT` (for example `GROUPTOTAL(score, category)` = the score of the rows with this row's category). Used by the new weighted NFR Risk Assessment template (`scripts/merge-nfr-assessment.js`).
- Audit log of settings changes with a mandatory reason and comments, shown as a clean plain-language table; export to CSV; retention with export before clearing.
- Backup and restore of all settings in selectable parts (replace or add missing only), with a safety backup and audit entry.
- **Controls now take any number of rules.** Each rule has its own people/teams, work item types, message and an on/off switch, and works as *Comments only* or *Lock specific fields* (for example Group 2 cannot edit two Epic fields, Group 3 three other fields). When a person is in several groups the stricter result applies. Your existing comment-only setting becomes “Rule 1” automatically; backups made before this still restore.
- Settings and capacity editing for project administrators only; new **Controls** tab with comment-only access on the work item form.
- Per-column display format for months and dates; configurable default allocation %; team from Azure DevOps team/group membership with optional override.
- Calculated Epic fields: Read-only Value control supports dates and yes/no; outputs corrected when the work item is opened.
- Hub tabs redesigned (single line, count badges).
